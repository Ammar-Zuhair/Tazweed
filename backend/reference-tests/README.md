# إعادة اختبار المخطط

من هذا المجلد، باستخدام lockfile المرفق:

```bash
npm ci --ignore-scripts --no-audit --no-fund
npm test
node phase-00-review.mjs
```

تستخدم الاختبارات PGlite 0.5.12 (محرك PostgreSQL/WASM في الذاكرة)، ولا تتصل بقاعدة إنتاج ولا تحتاج حسابًا خارجيًا. الاختبارات المرجعية في `schema.test.mjs` تتحقق من رفض 22 حالة مخالفة للقيود. يبقى المخطط المرجعي في `../database/schema.sql` دون تعديل خلال مراجعة 00.

`phase-00-review.mjs` يعد الجداول فعليًا من `pg_tables` ويتحقق من وجود 56 جدولًا، ويعيد إنتاج 17 حالة موثقة في [مراجعة المرحلة 00](../../REVIEW_00.md). يخرج JSON مع بصمة المخطط ونتائج الحالات. كل حالة تستخدم معاملة يجري التراجع عنها؛ كل البيانات وهمية وداخل الذاكرة.

`observed: "allowed"` يعني أن SQL الحالي سمح بالعملية؛ بعض هذه العمليات يجب أن يرفضها الخادم لاحقًا. exit 0 يعني أن نتائج التشخيص طابقت المراجعة، ولا يعني أن قواعد التطبيق متحققة. رمز مثل 23503/23505/23514/P0001 يشير إلى رفض القيد المتوقع. عند تعديل المخطط مستقبلًا تعاد مراجعة هذه التوقعات بدل إبقاء فجوة لمجرد إمرار التشخيص.

ليست هذه اختبارات تطبيق أو API أو صلاحيات أو تزامن خادم متعدد الاتصالات أو أجهزة. لا تنقل بيانات الاختبار إلى الإنتاج. نتائج تنفيذ 2026-10-28 محفوظة في [دليل الفحوص](../docs/progress/phase-00-checks.json).
