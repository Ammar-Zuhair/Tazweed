# دليل المالك لأسماء backend/.env

هذا الدليل يغطي **الأسماء الـ 49 الموجودة فعليًا في `backend/.env` عند تسليم 11**. لا يعرض أي قيمة سرية. هناك مفاتيح دخول سرية، ومعرّفات عامة، وعناوين، وقرارات سياسة، وإعدادات تقنية؛ لا تحتاج شراء 49 مفتاحًا. الملف المحلي مستبعد من Git وصلاحيته 600، والمثال القابل للرفع هو `.env.example`.

## ما يحتاج قرارك أولًا

| القرار | المطلوب منك | أثره |
|---|---|---|
| الجهة والدعم | الاسم القانوني المسؤول، هاتف دعم يمني فعّال، وبريد خصوصية تتابعه | يظهر في الخصوصية والشروط والدعم والحذف. لا يكفي اسم التطبيق بدل الجهة المسؤولة. |
| الحذف والاحتفاظ D19 | اعتماد نص السياسة ومدد البيانات الشخصية والإثباتات والتحقق، وكيفية التعامل مع النصوص المالية الحرة والالتزامات | يمنع نقصه قبول السياسة النهائية. لا نختار مدة قانونية عنك ولا نمحو دفتر المال بمجرد تعبئة متغير الإثباتات. |
| النسخ D20 | مدة النسخ ومكانها وتشفيرها وآلية انتهاء النسخ وحذفها، والميزانية و RPO/RTO | RPO أقصى مقدار بيانات تقبل فقده مقاسًا بالوقت، و RTO المدة المستهدفة لاستعادة الخدمة. متغير السياسة لا ينشئ نظام نسخ؛ التنفيذ التشغيلي في 12. |
| حدود الشهر D15 | اعتماد `Asia/Aden` أو منطقة أخرى بدل UTC المستخدم الآن للمعاينة الموسومة | يحدد بداية ونهاية الشهر في PDF؛ التخزين يبقى بتوقيت UTC. لم يعتمد Asia/Aden تلقائيًا. |
| النطاقات | نطاق API عام HTTPS، نطاقات الويب، ونطاق صور R2 العام | الهاتف ورابط الحذف العام يحتاجان وصولًا دون بوابة دخول remote. نفق Expo الحالي للمراجعة مؤقت. |
| OTP | اختيار SMS أو WhatsApp ومزود يدعم أرقام اليمن، وعقده وتكلفته/قوالبه | المحول الحالي بوابة HTTPS بعقد محدد أدناه؛ لا يوجد مزود مختار أو مفتاح شركة مخمّن. |
| الصور والإثباتات | حساب Cloudflare ووعاءان منفصلان ونطاق عام، مع قرار موقع البيانات | صور الكتالوج عامة، والإيصالات والشكاوى خاصة. لا نشر للإثباتات على نطاق الصور. |
| الطريق | خدمة OSRM مملوكة أو مزود متوافق وعنوانه، وبيانات الفروع/التغطية الفعلية | لا يعتمد التشغيل على خادم OSRM التجريبي العام. |
| التطبيقات والإشعارات | ملكية حساب Expo ومشاريعه الثلاثة، هويات Android/iOS، و Firebase/Apple عند اختبار Push | اختبار Push و OTA يحتاج بناءً مثبتًا على جهاز؛ Expo Go باقٍ للمراجعة. لا بناء أو نشر تلقائي في 11. |
| بيانات العمل | الفروع وإحداثياتها والتغطية والتعرفة والأسعار والأرصدة والمستفيدون ونسب الموصل وصلاحيات الموظفين | تدخل عبر الإدارة/قاعدة البيانات، وليست مفاتيح.env. |

راجع [عينة التقرير](progress/phase-11-evidence/monthly-sales.pdf) للتأكد من العربية وطريقة فصل الأرقام. بياناتها اختبار معزول وليست مبيعات حقيقية. بعد إدخال الإعدادات وطلب الفحص المجمع نختبر المزودات والحذف من التطبيق والمتصفح، ثم نسجل النتيجة الفعلية. حتى ذلك الحين تبقى السياسة و OTP/R2/Routing/Push غير مهيأة، و`ready` يعرض النقص صراحة.

## 1. رموز التحقق OTP — ثلاثة أسماء

OTP يعني رمز استخدام واحد، وليس كلمة مرور دائمة. اختيار وسيلة SMS/WhatsApp وحساب مزودها قرارك. العقد الحالي: `POST` عبر HTTPS بجسم `{phone, code, purpose, app, challengeId}` و`Authorization: Bearer …`؛ البوابة تتولى الإرسال. إذا اخترت مزودًا بواجهة مختلفة يلزم محول مناسب قبل تجربته، ولا يكفي وضع مفتاح Twilio أو Meta في الحقل.

| الاسم | معناه | من أين تأتي قيمته؟ |
|---|---|---|
| `OTP_PROVIDER` | نوع محول الإرسال | يبقى `UNCONFIGURED` حتى التجهيز؛ المحول المنفذ اسمه `https-gateway`. هذه قيمة اختيار وليست سرًا. |
| `OTP_PROVIDER_URL` | عنوان HTTPS الكامل الذي يستقبل طلب الإرسال | من المزود المتوافق أو من مشغل بوابة تملكها. لا تضع توكنًا في العنوان. |
| `OTP_PROVIDER_TOKEN` | السر الذي يسمح لخادمنا باستدعاء تلك البوابة | يصدره المزود/مشغل البوابة. سري وخادمي؛ لا يوضع في التطبيق. |

لا يوجد رابط استخراج واحد قبل اختيار المزود. رقم مرسل WhatsApp أو Sender ID وقالب المصادقة، إن طلبها المزود، تضبط في حسابه/محوله؛ لا نضيف أسماء أسرار لا تستهلكها الشيفرة.

## 2. Cloudflare R2 — ستة أسماء

R2 تخزين ملفات متوافق مع S3. من لوحة Cloudflare افتح R2 وأنشئ وعاءً عامًا لصور الكتالوج، وآخر خاصًا للإيصالات والشكاوى وملفات الرفع المؤقتة. من Account Details → Manage API Tokens أنشئ بيانات S3 بصلاحية Object Read & Write للوعاءين فقط. احفظ السر عند ظهوره؛ ليس هو Cloudflare Global API Key. [تعليمات المصادقة الرسمية](https://developers.cloudflare.com/r2/api/tokens/).

| الاسم | معناه | من أين تأتي قيمته؟ |
|---|---|---|
| `R2_ACCOUNT_ID` | معرّف حساب Cloudflare صاحب التخزين،32 حرفًا سداسيًا | Account Details في لوحة R2. معرّف وليس السر. |
| `R2_ACCESS_KEY_ID` | معرّف مفتاح S3 المستخدم لتوقيع طلبات الملفات | نتيجة إنشاء بيانات API في R2. يبقى خادميًا. |
| `R2_SECRET_ACCESS_KEY` | السر المقابل لمعرّف المفتاح | النتيجة نفسها، ويعرض عند الإنشاء؛ خزنه بأمان. |
| `R2_PUBLIC_BUCKET` | اسم وعاء الصور العامة بالضبط | الاسم الذي تختاره عند إنشاء الوعاء العام. |
| `R2_PRIVATE_BUCKET` | اسم وعاء الإثباتات و staging بالضبط | اسم الوعاء الثاني؛ اترك الوصول العام معطلًا. |
| `R2_PUBLIC_BASE_URL` | جذر HTTPS لقراءة الصور العامة، دون مسار ملف أو query | Custom Domain تربطه بالوعاء العام؛ مثال توضيحي فقط `https://images.example.com`. |

للنطاق العام استخدم Custom Domain عند التشغيل؛ `r2.dev` مخصص للتطوير. [إتاحة الوعاء العام](https://developers.cloudflare.com/r2/buckets/public-buckets/). محولنا الحالي يستعمل نقطة S3 العالمية `<account_id>.r2.cloudflarestorage.com`؛ إذا احتجت وعاءً ذا jurisdiction خاص مثل EU/US فأبلغنا قبل التجهيز لأنه يحتاج نقطة مختلفة.

يلزم CORS لمصادر الويب الفعلية ورفع PUT، وسياسة تنظيف `staging/` دون مسح `private/` الذي يحتفظ بالإثباتات. يراجعها المشغل مع صلاحية حذف الكائنات قبل الفحص. [CORS الرسمي](https://developers.cloudflare.com/r2/buckets/cors/). لا تحتاج شراء مفتاح إضافي لكل صورة أو لكل تطبيق.

## 3. حساب الطريق — ستة أسماء

OSRM محرك حساب طريق؛ استضافته أو التعاقد مع بوابة متوافقة قرار منفصل عن عرض الخريطة. الخريطة الحالية OpenFreeMap مع MapLibre لا تحتاج مفتاح عرض جديدًا. [عقد OSRM الرسمي](https://project-osrm.org/docs/v5.24.0/api/)، و[قيود محول المشروع](ROUTING.md).

| الاسم | معناه | المصدر/ما تفعله |
|---|---|---|
| `ROUTING_PROVIDER` | اختيار المحول | `UNCONFIGURED` الآن، ثم `osrm` عند تجهيز الخدمة. |
| `ROUTING_BASE_URL` | جذر HTTPS لخدمة OSRM المملوكة | من مشغل الخادم أو المزود المتوافق؛ لا تضف `/route/v1/…` بنفسك. خوادم demo العامة مرفوضة في التطبيق. |
| `ROUTING_API_KEY` | توكن Bearer لحماية بوابة الطريق | من مشغل البوابة إذا كانت محمية؛ اختياري، فـ OSRM الأساسي لا يصدر مفتاحًا بذاته. |
| `ROUTING_PROFILE` | اسم ملف القيادة الذي تقبله الخدمة | الافتراضي `driving`؛ يراجعه المشغل مع إعداد OSRM. ليس اختيار نوع مركبة مضمونًا بمجرد تغيير النص. |
| `ROUTING_TIMEOUT_MS` | مهلة اتصال الطريق بالمللي ثانية | `5000` افتراضيًا، أي 5 ثوانٍ؛ إعداد تقني لا تستخرجه من شركة. |
| `ROUTING_MAX_SNAP_M` | أقصى إزاحة مقبولة بين الدبوس ونقطة الطريق بالمتر | `200` افتراضيًا؛ حماية جودة، وليس نصف قطر تغطية التوصيل. |

## 4. Expo Push — ستة أسماء

Expo هو وسيط إرسال إشعارات الهاتف عبر FCM في Android و APNs في iOS. جهّز 3 مشاريع EAS تملكها، واحدًا لكل تطبيق. معرّف Project ID موجود في Project Settings وفي إعداد `extra.eas.projectId`. [إعداد Push الرسمي](https://docs.expo.dev/push-notifications/push-notifications-setup/).

| الاسم | معناه | من أين تأتي قيمته؟ |
|---|---|---|
| `PUSH_PROVIDER` | اختيار محول الإشعارات | يبقى `UNCONFIGURED` حتى التجهيز؛ المحول المنفذ `expo`. |
| `EXPO_ACCESS_TOKEN` | توكن سري لخادمنا لإرسال Push مع Enhanced Push Security | Expo Account Settings → Access Tokens؛ اختر حسابًا وصلاحيات مناسبة لمشاريعك، وفعل حماية Push. [توكنات Expo](https://docs.expo.dev/accounts/programmatic-access/)، [حماية الإرسال](https://docs.expo.dev/push-notifications/sending-notifications/). |
| `EXPO_CUSTOMER_PROJECT_ID` | UUID مشروع تطبيق العميل | Project Settings لمشروع العميل. معرّف عام. |
| `EXPO_ADMIN_PROJECT_ID` | UUID مشروع تطبيق الإدارة | Project Settings لمشروع الإدارة. معرّف عام. |
| `EXPO_COURIER_PROJECT_ID` | UUID مشروع تطبيق الموصل | Project Settings لمشروع الموصل. معرّف عام. |
| `PUSH_TIMEOUT_MS` | مهلة استدعاء Expo بالمللي ثانية | الافتراضي `5000`؛ إعداد تقني. |

`EXPO_ACCESS_TOKEN` اسم يقرأه **خادم هذا المشروع**؛ اسم التوكن القياسي في أداة EAS CLI هو `EXPO_TOKEN`. لا تستبدل أحدهما عشوائيًا ولا تضف متغير CLI إلى HTTP لمجرد التشابه.

هناك اعتمادان لا يدخلان في backend/.env: ملف Service Account الخاص بـ FCMv1 من Firebase/Google Cloud، ومفتاح APNs `.p8` مع Key ID و Team ID من Apple Developer. يجهزان عبر EAS Credentials للتطبيقات المطلوبة. ملف `google-services.json` الخاص بتهيئة Android مختلف عن Service Account السري، ويستخدمه البناء عبر متغير ملف EAS `GOOGLE_SERVICES_JSON`. [خطوات FCMv1 الرسمية](https://docs.expo.dev/push-notifications/fcm-credentials/)، [اعتمادات توقيع التطبيق](https://docs.expo.dev/app-signing/app-credentials/).

Expo Go الحالي SDK57 لا يثبت عمل Push عن بعد؛ ذلك يحتاج بناء تطبيق مثبت واعتمادات المنصتين. لم يُنشأ بناء أو ينشر OTA في 11. [حدود Go للإشعارات](https://docs.expo.dev/push-notifications/faq/).

## 5. هويات التطبيقات وعنوان API — تسعة أسماء

هذه بيانات عامة تدخل في metadata البناء وليست أسرارًا. هويات Android/iOS يجب أن تعتمدها وتملكها، وتطابق تسجيل Firebase/Apple/EAS والمتاجر قبل بناء إنتاج. عنوان API هو جذر الخادم HTTPS **دون `/api/v1`** لأن العميل يضيفه، ويمكن أن يكون نفسه للتطبيقات الثلاثة. يجب أن يصل إليه الهاتف دون تسجيل دخول remote. [إعدادات الإصدار في المشروع](RELEASES.md).

| الاسم | معناه | المصدر/القرار |
|---|---|---|
| `CUSTOMER_API_URL` | جذر API لتطبيق العميل | نطاق الخادم العام الذي تعتمده. |
| `ADMIN_API_URL` | جذر API لتطبيق الإدارة | نطاق الخادم العام؛ يمكن مطابقته للعميل. |
| `COURIER_API_URL` | جذر API لتطبيق الموصل | نطاق الخادم العام؛ يمكن مطابقته للعميل. |
| `CUSTOMER_ANDROID_PACKAGE` | هوية Android الدائمة للعميل | اسم reverse-DNS تختاره وتربطه بتطبيق Google Play/Firebase، مثل `com.example.customer` للتوضيح فقط. |
| `ADMIN_ANDROID_PACKAGE` | هوية Android الدائمة للإدارة | اسم مستقل معتمد ومتاح لك. |
| `COURIER_ANDROID_PACKAGE` | هوية Android الدائمة للموصل | اسم مستقل معتمد ومتاح لك. |
| `CUSTOMER_IOS_BUNDLE_IDENTIFIER` | هوية iOS الدائمة للعميل | تسجلها في Apple Developer → Identifiers وتطابق App Store Connect. |
| `ADMIN_IOS_BUNDLE_IDENTIFIER` | هوية iOS الدائمة للإدارة | هوية مستقلة مسجلة بحساب Apple المعتمد. |
| `COURIER_IOS_BUNDLE_IDENTIFIER` | هوية iOS الدائمة للموصل | هوية مستقلة مسجلة بحساب Apple المعتمد. |

لا تعتمد أسماء preview الحالية كهويات متجر تلقائيًا. نفق Expo مناسب للمراجعة، ولا يغني عن عنوان التشغيل المستقر أو اعتماد هويات البناء.

## 6. الخادم والجلسات — ستة أسماء

الأسماء الأربعة الأولى جاهزة محليًا في `.env.runtime.local`. الفراغ المقصود في backend/.env يسمح بوراثتها؛ لا تحتاج جلبها من مزود OTP أو Cloudflare. عند نقل التشغيل إلى بيئة أخرى يولدها المشغل ويضبط قاعدة بياناتها وصلاحياتها بصورة مستقلة.

| الاسم | معناه | المصدر/ما يلزمك |
|---|---|---|
| `DATABASE_URL` | اتصال PostgreSQL بحساب HTTP محدود الصلاحيات؛ قد يحتوي كلمة مرور | محليًا جاهز من تهيئة قاعدة المشروع. لاحقًا من مشغل قاعدة بيئة التشغيل. لا تستخدم اتصال مالك migrations. |
| `JWT_PRIVATE_KEY` | مفتاح Ed25519 الخاص لتوقيع توكنات الجلسة | يولده الخادم/المشغل؛ جاهز محليًا وسري. لا تغيّره عشوائيًا لأن تدويره يؤثر في الجلسات. |
| `JWT_PUBLIC_KEY` | المفتاح المطابق للتحقق من توقيع الجلسة | يولد مع الخاص. ليس سرًا تشفيريًا، لكن يحفظ في الخادم وفق حدود المشروع. |
| `OTP_HMAC_SECRET` | سر داخلي لتجزئة بيانات التحقق وربطها وحمايتها | يولد عشوائيًا محليًا، 32 بايتًا على الأقل ممثلة hex. ليس رمز OTP للمستخدم ولا توكن شركة الإرسال. |
| `PUBLIC_BASE_URL` | عنوان الخادم العام الذي تستند إليه الروابط والصفحات | نطاق HTTPS تعتمده؛ المسارات مثل `/privacy` و`/delete-account` تعمل عليه. عنوان remote المحمي للمراجعة لا يكفي كرابط حذف عام دائم. |
| `CORS_ALLOWED_ORIGINS` | مصادر الويب المسموح لها باستدعاء API | عناوين origin دقيقة مفصولة بفواصل: scheme+host+port دون مسار. يضبطها المشغل من نطاقات الويب؛ لا تستخدم `*`. |

تحميل HTTP: `.env.runtime.local` ثم القيم غير الفارغة من backend/.env ثم متغيرات العملية. ملف `.env.local` يحوي اتصال مالك migrations ويخص أداة الترحيل فقط. لا تنقل محتواه إلى HTTP. [تفاصيل التحميل](ENVIRONMENT.md#التحميل-وإعادة-التشغيل).

## 7. مراجعة الإيصالات — اسمان

التحويل الحالي يدوي؛ لا تحتاج مفتاح Stripe أو PayPal أو بوابة دفع. المستفيدون ووسائل التحويل تسجل من الإدارة.

| الاسم | معناه | المصدر/الافتراضي |
|---|---|---|
| `RECEIPT_ATTEMPT_LIMIT_PER_HOUR` | أقصى محاولات صور الإيصال للعميل في الساعة بما فيها التصحيح | `6` افتراضيًا؛ قرار حدود تشغيل عند الحاجة. |
| `RECEIPT_REVIEW_ALERT_MINUTES` | مدة انتظار المراجعة قبل إظهار تنبيه | `60` دقيقة افتراضيًا. **لا تنهي حماية الحجز ولا تعتمد المال تلقائيًا**. |

## 8. السياسة والدعم والتقارير — أحد عشر اسمًا

هذه قيم يعتمدها المالك بعد مراجعة التزاماته؛ لا يصدرها أي مزود API. لا توجد مدة قانونية اختيرت نيابة عنك. الحدود البرمجية للمدد أعداد أيام صحيحة 0–36500، وهدف المعالجة 1–36500؛ قبول الرقم فنيًا لا يعني مناسبة السياسة قانونيًا.

| الاسم | معناه الدقيق | من يحدده؟ |
|---|---|---|
| `STORE_LEGAL_NAME` | اسم الجهة المسؤولة عن البيانات والخدمة | أنت وفق بيانات الجهة الفعلية. |
| `STORE_SUPPORT_PHONE` | هاتف دعم متابع بصيغة `+967` ثم 9 أرقام | أنت؛ ليس رقم مرسل OTP ولا مفتاح API. |
| `PRIVACY_CONTACT_EMAIL` | البريد الذي يتلقى استفسارات وطلبات الخصوصية | أنت من بريد تملكه وتتابعه. |
| `PRIVACY_POLICY_VERSION` | رقم/اسم نسخة السياسة | أنت عند اعتماد النص؛ مثل `1.0` للتوضيح فقط. |
| `PRIVACY_POLICY_APPROVED_AT` | تاريخ الاعتماد الفعلي بصيغة `YYYY-MM-DD` | أنت؛ لا نملأه بتاريخ كتابة الشيفرة. |
| `PRIVACY_PERSONAL_RETENTION_DAYS` | مدة إبقاء بيانات العنوان/التواصل في snapshot الطلب المغلق قبل تعمية المشمول، من آخر حدث مرتبط | تعتمدها وفق سبب الاحتفاظ؛ إغلاق الالتزامات شرط، وليست مهلة لتجاهله. |
| `TRANSACTION_RETENTION_DAYS` | مدة إبقاء ملفات الإثبات الخاصة قبل الحذف، من الأحدث بين إنشاء الملف ومحو هوية الحساب | تعتمدها وفق احتياج المال والالتزام. **لا تحذف دفتر المعاملات أو كل نص مالي حر**. |
| `PRIVACY_SECURITY_RETENTION_DAYS` | مدة تنظيف تحديات التحقق المنتهية | تعتمدها لأغراض الأمان؛ لا تضبط حذف audit. تحديات الحساب نفسه تمحى عند محو هويته. |
| `PRIVACY_BACKUP_RETENTION_DAYS` | مدة النسخ التي تعلنها السياسة | تعتمدها مع خطة نسخ حقيقية؛ ليست أداة حذف نسخ أو تنفيذ نسخ في 11. |
| `PRIVACY_REQUEST_TARGET_DAYS` | هدف مدة معالجة طلب الحذف | تعتمدها بما يستطيعه التشغيل؛ لا تتجاوز حجزًا أو التزامًا مفتوحًا تلقائيًا. |
| `REPORT_TIME_ZONE` | منطقة IANA لحدود الشهر في التقرير | UTC للمعاينة حاليًا. `Asia/Aden` مقترح باقٍ ينتظر قرارك D15. |

عند نقص السياسة يظهر أنها غير مكتملة، ويمكن استقبال طلب الحذف والتحقق وإبطال جلساته، لكن المحو المؤجل يحتاج مراجعة. لا يبدأ production بسياسة ناقصة. المراجع المالية التي تبقى والنصوص الحرة وأثر النسخ تحتاج نصًا وإجراءً محددين قبل قبول D19/D20. [سلوك الحذف وحدوده](REPORTS_PRIVACY.md).

## كيف تسلم القيم ونختبرها

ضع أسرار المزودات في **Containers → Secrets** بأسماء المشروع أعلاه، أو أدخلها محليًا في `backend/.env`؛ لا ترسلها في الرسائل. حقول السياسة والنطاقات والمعرّفات ليست أسرارًا ويمكنك إبلاغنا بها. ملف `/workspace/.env` الذي تديره المنصة مختلف عن `backend/.env` ولا يقرأه HTTP تلقائيًا؛ عند طلب الفحص نربط الأسماء اللازمة فقط بالخدمة أو ننقلها إلى الملف الخادمي دون طباعتها، ثم نعيد التشغيل. خدمات systemd الحالية لا تكتسب متغيرات مضافة بمجرد حفظها في الواجهة.

أبقِ اختيارات المزودات `UNCONFIGURED` حتى تكتمل قيمها، ثم اطلب الفحص المجمع. نتحقق أولًا من التهيئة دون كشف الأسرار، ثم OTP حقيقي بموافقتك على الأرقام والتكلفة، ورفع/قراءة/حذف R2 وصلاحياته، ومسار فعلي بين نقاط تحددها، ثم Push/الهاتف/المشاركة و OTA ضمن بناء مأذون. لا يُعد `ready=200` وحده دليل عمل المزود. لا يلزم أي مفتاح جديد لمحرك PDF؛ ينفذ محليًا.

رُوجعت هذه المصادر الرسمية في 6 نوفمبر 2026، وقد تتغير تسميات لوحات المزودات. لم تشترَ خدمة ولم يُرسل OTP ولم يُنشر أي بناء أو تحديث أثناء إعداد الدليل.
