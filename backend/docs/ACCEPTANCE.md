## اختبارات الخدمات المطلوبة في مراحلها — غير منفذة الآن

- إرسال/معاينة: preview لا يكتب أو يحجز؛ submit ينتظر المدير دون quote لطلب مفقود؛ إصدار المدير يجمع اختيار الفرع والعرض والحجز وoutbox ذريًا. governorate/catalogBranchId لا يتجاوزان فرع المحافظة، وتغير الفرع يحتاج قبولًا جديدًا دائمًا.
- السعر والتوفر: المنتج نشط وخصائصه الإلزامية مسجلة وقيمه نشطة، والفرع/المحافظة والوحدة نشطة وsellable والحر يكفي. فلاتر الزيت لا تعرض مقاس إطار. تغيير المحافظة يعرض أثره على السلة دون حذف صامت.
- عرض واحد: احسب توفير العروض المؤهلة للطلب كله، واختر الأكبر، ثم id ASC عند التساوي، بما في ذلك عرض يشمل عدة منتجات. لا stacking ولا جمع مع جملة معدلة ولا ادعاء حدود استعمال غير موجودة.
- الحجز: طلبان على آخر رصيد ينجح واحد ويأخذ الآخر409؛ لا انحراف counter/ledger. كل من expiry worker والتحويل والنقل والجرد والتأكيد يلتزم القفل والترتيب والمعاملة. وصول إيصال لا يفقد الحجز/السعر لمجرد مرور30 دقيقة؛ التنبيه بالتأخر وضوابط رفع تمنع الإساءة دون مهلة تحرير مفترضة.
- النقد: منتهي الحجز يعاد تسعيره ومراجعته؛ إذا لم تتغير أي حقيقة يسجل revalidation وإعادة الحجز ذريًا، وإذا تغيرت يصدر عرض جديد. لا اعتماد ادعاء «أعدت التحقق» من العميل، ولا تجاوز موافقته.
- المال: idempotency لكل approve/confirm/deliver/collect/remit/settle/reverse؛ إعادة نفس المفتاح تعيد نفس النتيجة، ومحتوى مختلف409. اختبار صرف وتوريد متنافسين لنفس البنود. الحالات الزائدة/الناقصة والمتأخرة والإيصال المرفوض وطلب الإلغاء لها نتيجة محفوظة.
- صلاحيات: العميل لا يرى طلبًا/إيصالًا لغيره، والموصل لا يرى غير مسند إليه أو سجل البلاغات أو الإيصالات المالية؛ الموظف محصور action+branch والنقل بنطاق الفرعين، وتحويل header/app لا يصعد صلاحية. تحصيل/توريد/عكس النقد وصرف العمولات والتحقق من المال والحذف صلاحيات منفصلة.
- OTP: تسجيل/دخول/استرداد/حذف بغرض واحد واستخدام واحد وحدود محاولة وHMAC، لا رموز في logs أو bypass، ورفض production إذا المزود غير مهيأ. اختبار تدوير refresh وإبطاله عند الحذف/تغيير كلمة المرور.
- حماية الملفات: PUT عشوائي محدود ثم completion يتحقق من magic bytes والحجم، receipt private لصاحب الطلب، GET موقّع قصير للمخول، ولا إدخال URL خاص إلى logs أو DB بدل object_key.
- الخصوصية: حذف من التطبيق والمتصفح فعلي، وإبطال sessions/push وحذف/تعمية snapshots والمرفقات وفق سياسة معتمدة؛ الدفاتر غير مفتوحة لتعديل عام. حساب مفتوح لا يمنع استقبال طلب الحذف، ولا مدة قانونية مختلقة.

## الواجهات والأجهزة والتشغيل — غير منفذة الآن

- Arabic RTL/Tajawal محلي، نصوص وأرقام قابلة للقراءة والتكبير، ثيمان، حالات loading/empty/error/retry/offline. اختبارات Android/iOS وبناء native، لا Expo Go كدليل دعم.
- فيديو العميل في video: فاتح ومظلم،4ثوانٍ، تخطٍ وصوت يتوقف عند التخطي والخلفية، لا يعاد عند navigation/foreground، فشل لا يمنع الدخول، احترام تقليل الحركة وكتم النظام. مواءمة imports وإعادة التصدير عند01 دون تجديد الأصول.
- صيانة customer تحجب catalog/preview/submit وتبقي الجاري وتفاعلاته الضرورية والدعم والخصوصية والحذف؛ لا توقف admin/courier. API نفسه يطبق ذلك.
- OTA بالخلفية للتشغيل التالي دون reload أثناء العمل؛ runtime/native وقنوات staging/production منفصلة، وتحديث إجباري له إصدار ورابط متجر فعليان قبل رفع minimum.
- إشعارات foreground/background/closed وصوت المهام على أجهزة فعلية ومركز إشعارات بديل؛ لا ضمان force-stop أو رفض الإذن.
- مواقع الفروع الحقيقية وتعرفة الطريق والتغطية ومزود Routing وبيانات R2/OTP/Push تختبر فعليًا عند ربطها، لا demo إنتاجي أو استضافة مفترضة.
- التقارير تفصل رسوم التوصيل الأصلية والخصم ورسوم العميل والعمولة والتحصيل والتوريد والتحويل والمبالغ المسواة، دون حساب الملغي/المرفوض مبيعات أو credit العكس عمولة جديدة. Asia/Aden مقترح لم يعتمد صراحة بعد.
- اختبار نسخ واستعادة وأعطال OTP/R2/Maps/Push دون فقد طلب. مدد الاحتفاظ وRPO/RTO والميزانية تنتظر المالك قبل تشغيل فعلي.

## دليل الإنجاز

مخرجات00 هي مرجع SQL ووثائق واختبارات معزولة فقط. في المراحل التالية يلزم typecheck/lint/build لما تغير، واختبارات خدمات وعقود مع PostgreSQL حقيقي متعدد الاتصالات، ومعاينات وأجهزة مناسبة للشاشات. لا تزعم نجاح مسار لأن جدوله موجود أو لأن SQL يقبل fixture مختبرًا.
