# المرحلة08 — الطلبات والجملة والتحويل والنقد

نُفذ نطاق08 بعد قراءة `remember.md` وتقرير07 وخطة08 ومراجعها من المستودع: قرارات المالك وسجل المشكلات وMASTER_PROMPT والمتطلبات والقرارات، وقواعد العمل وقاموس البيانات وSQL وAPI والأمان والقبول وشاشات العميل والإدارة. لم يوجد عائق سابق يمنع التنفيذ المستقل. بقي فحص المزودات الحقيقية مؤجلًا بطلب المالك، ولم تبدأ09.

## النتيجة

العميل يرسل الطلب إلى PostgreSQL، ثم يختار المدير فرع التنفيذ ويصدر عرضًا ثابتًا وحجزًا أوليًا30دقيقة في معاملة واحدة. يقبل العميل النسخة الحالية صراحة، ويختار التحويل أو النقد. تعليمات التحويل تحفظ قبل عرض الجهة والمستفيد والرقم؛ لكل تحويل محاولات صور ومراجعات مستقلة. الإيصال يحمي الحجز والسعر دون انتهاء آلي. التأكيد النقدي لا يحتاج إيصالًا ولا يسجل تحصيلًا أو عمولة.

المبالغ والحالات والقبول والحجز والمال من الخادم. لا نجاح مالي محلي أو fallback إلى البيانات التجريبية القديمة. واجهات العربية وRTL وTajawal والثيمان وخلفية العميل وExpo Go57 محفوظة.

التفاصيل والعقود في [ORDERS](../ORDERS.md) و[API](../API.md) و[OpenAPI08](../openapi.phase08.json). استجابات التفاصيل تصف أنواع المبالغ والحالات والبنود والمحاولات والحجوزات والتسويات، مع حقول إضافية مسموحة؛ العلاقات الدلالية والحراس موثقة ومختبرة، وليست كل استجابةCRUD مخططًا مغلقًا بالكامل.

## الملفات وقاعدة البيانات

- `backend/src/orders/{contracts,pricing,core,service,finance,views,routes,worker,openapi}.ts` وربطها بالتطبيق وhealth وreadiness. قراءة التفاصيلREPEATABLE READ READ ONLY، والأحداث والتدقيق وoutbox ضمن معاملات الأوامر.
- `0005_order_workflow.sql`: فرع تاريخي للاستثناء، وغرض إثبات مالي خاص، وفهارس الطلبات والدفع والتأخر والتفرد لصورة الإيصال ولمرجع المال الخارجي، وحارسappend-only للبنود الأصلية. المجموع72جدولًا و50trigger؛ المخطط المرجعي و0001–0004 محفوظة. صلاحياتruntime للأعمدة المحروسة فقط؛ الدفاتر INSERT-only، ودور التعمية مستقل.
- `customer-app/src/live/{orders,checkout,operations,operation-queue,connection}` ومسارات الطلب والعرض والدفع وطلباتي. بطاقات السلة تبقى مسودة؛ الإرسال لا يعتمد معاينة07 القديمة.
- `admin-app/src/live/{orders,methods,operations,operation-queue,connection,workspace}` ومسارات الطلبات ووسائل التحويل. حقول الأسعار تميز الحبة والكرتون، ويختار الموظف سبب القرار وحكم الحجز صراحة.
- الموصل لم يتلق خدمات مهام أو تحصيل أو عمولة في08؛ تغير رقم المرحلة العام فيmetadata فقط. لا INSERT من08 إلىorder_assignments أوcash_collections أوcourier_earnings.
- اختبارات08 والنقل والطابور ورحلتَي المتصفح وجامع الأدلة، وتحديث المراجع والبيئة ومراجعة الواجهات وسجل المشكلات والذاكرة. لا اعتماديات جديدة أو تغييرSDK.

قراءةorder_private_details بواسطة دور الخادم أصبحت لازمة لعرض الطلبات بملكيتها ونطاقها. عُدّل توقع05 القديم الذي كان يمنع قراءتها في مرحلة الهوية فقط؛ بقي منع تعديلها/تعميةها منruntime أو افتراض دورprivacy، مع اختباراتAPI لعزل المالك والفروع. منح INSERT للطلبات والحجوزات08 لا يجعل معاينة07 تكتب؛ اختبارات غياب كتاباتها باقية.

## الفحوص المعتمدة

نجح **186 اختبارًا**:107 للخادم والنقل، تشمل30 حالة جديدة لـ08؛ و6 لطابور العمليات في التطبيقين بمحولات تخزين/نقل معزولة؛ و73 لحراسSQL المرجعية على PostgreSQL TCP فعلي. لا إخفاق أو اختبارات متجاهلة. اختبارات SQL المرجعية التي تشمل تصميم النقد/العمولة لا تعني تنفيذ خدمات09.

شملت الحالات: التحويل المطابق والنقد بلا إيصال، والجملة، و2.8كم→2، وتغيير الفرع بسعر مساوٍ وقبول جديد، ونقل الرصيد المعتمد بعد المراجعة، وانتهاء النقد مع التطابق/تغير السعر، وعدم انتهاء حجز الإيصال، وتنبيه التأخر دون تكرار، وتصحيح الصورة لنفس التحويل، ومرجع تحويل مكرر عبر طلبين، ونقص/زيادة المال وتسويتهما، ومرجع تسوية مكرر، وآخر مخزون متزامن، وإلغاء ما قبل/بعد الإيصال ومنعه بعد التأكيد. فُحصت المبالغ الكسرية والحقول المزورة والعناوين وخصوصيةsnapshot والتفويض التاريخي والحالي، وإعادة فحص الصلاحيات قبل ردidempotency المحفوظ، ومسارات الإدارة بحالات أحرف مختلفة.

نجحت **10 جولات UI و23 لقطة**: رحلة التجزئة بالتحويل وتغيير الفرع والتصحيح والتحقق والتأكيد؛ والجملة النقدية مع فقد إقرار الخادم بعد الالتزام ثم إعادة المحاولة دون طلب مكرر؛ وتسوية نقص مالي بإثبات خاص وإغلاق الاستثناء والتأكيد؛ ومصفوفة ثيمين×360/390/1024 لشاشتي العميل والإدارة؛ وفحص مستقل لإقرارrefresh قديم بعد الخروج والدخول بحساب آخر. لم يظهر طلب الحساب الأول في الثاني، ولا أخطاءpageerror أو طلبات مزود خارجي في الرحلة الرئيسية.

المتصفح يتصل بخادم وقاعدة PostgreSQL مؤقتة حقيقيين. OTP محولCaptureProvider داخلprocess، وRouting محولTestRouting، والتخزينTestStore؛ التحقق من بايتات الصورة ومعالجتها فعليان، لكن الرفع ليسR2. في فحص الجلسة حُقن401 واحد لبدء التجديد، ثم أُخّر **رد تجديد حقيقي** حتى اكتمال دخول الحساب الآخر. لا DTO أعمال وهمية أو حالة مالية محقونة فيReact، ولا حسابات أو جهات تحويل تجريبية مزروعة في قاعدة المراجعة.

تأخير التخزين وإعادة إنشاء طابوره في الاختبارات محاكاة لمحول التخزين، لا تجربةKeychain/Keystore. تجربة الهاتف الفعلية وصوت الافتتاحية وSecureStore وR2 والطريق وOTP الحقيقيين باقية.

نجحت فحوص الأنواع للتطبيقات الثلاثة والخادم وبناء الخادم، وتصديرات الويب الثلاثة وحزمHermes لـAndroid وiOS لكل تطبيق (6حزم)، وexpo install --check ومطابقةOpenAPI. نجح فحص467ملفًا ومخرجًا، منها293مخرج حزم/أصول منشورة، بحثًا عن أسماء إعدادات الخادم وقيم أسراره المعروفة؛ لا تطابق محظور. فحص الأنفاق عبرGo وجمع التقرير الآلي مبينان في قسم التشغيل والأدلة أدناه.
