## أبرز النتائج

1. SQL ينشئ 56 جدولًا فعلًا، وقيود الرصيد والحساب والمفاتيح وتفرد الاستحقاق والتسوية تعمل ضمن نطاق الاختبارات المرجعية.
2. F01: عرض checkout الدائم يشترط طلبًا، بينما وصف API يضعه قبل إنشاء الطلب. يلزم توحيد معنى المعاينة والحجز وsubmit قبل تنفيذ 07/08.
3. F02: المرجع المركب للحجز إلى فرع الطلب المتغير يمنع إعادة اختيار الفرع حتى بعد تحرير الحجز. يلزم تعديل التصميم قبل migrations في 05 مع حفظ التاريخ.
4. F03/F04/F05: عدم قابلية تعديل الوحدات/البنود التاريخية يحتاج حراسًا؛ إعادة رفع إيصال مرفوض بنفس الرقم تحتاج محاولات محفوظة؛ بيانات التحويل تحتاج snapshot قبل تحويل العميل لا بعد رفع الإيصال فقط.
5. F06/F07: تعويض التسويات والحالات المالية الاستثنائية يحتاج تصميمًا صريحًا؛ قاموس قبول العرض يعرض شرطًا مختلفًا عن SQL الفعلي، ولا ينبغي تشديده بما يمحو أثر قبول سابق.
6. F08–F11: استكمال عقود الإدارة والإلغاء والخصومات، وضبط معنى التغطية، وخطة تعمية snapshots، ومواءمة مراجع الفيديو إلى video في المرحلة 01.
7. R06–R12 لا تمثل خدمات مخفقة: لا خدمات منفذة أصلًا، وهذه قواعد معلنة في DATABASE.md لتنفذها معاملات الخادم. لا اختبار صلاحيات أو تزامن ناجح يُستنتج من PGlite.

## الفحوص المنفذة

بيئة الفحص: Node v22.23.4 وnpm 10.9.9 وPGlite 0.5.12. تفاصيل وقت التنفيذ والبصمة في JSON المرفق.

```bash
cd /workspace/backend/reference-tests
npm ci --ignore-scripts --no-audit --no-fund
npm test
node phase-00-review.mjs
```

التثبيت الأول في هذه المرحلة تم بـ`npm install --ignore-scripts --no-audit --no-fund` لإنشاء lockfile؛ أُعيد التحقق من التثبيت المقفل ونجاح الأمرين بعد توثيق الأداة. النتيجة: 22/22 اختبار رفض مرجعي و17/17 تشخيصًا متوقعًا، وعدد الجداول 56 باستعلام فعلي. التشخيص يثبت سلوك SQL الحالي؛ `allowed` لبعض العمليات دليل على حاجة الخادم لحارس وليست موافقة عليها.

فُحصت الحزمة قبل تحرير remember.md: 100/100 بالحجم وSHA-256، مع الفيديوهين في `customer-app/video`. حُفظت البصمة الأصلية لـschema.sql في دليل الفحص ولم يتغير المخطط.

فُحصت أيضًا صحة JSON والروابط المحلية للمخرجات، وصياغة سكربت المراجعة، و`git diff --check` للملفات المعدلة، ونطاق الملفات المجهزة للرفع لاستبعاد الأسرار وملفات تشغيل الوكيل. تسليم Git يكون بـcommit للملفات السبعة أعلاه ثم push إلى `origin/main` والتحقق من تطابق SHA المحلي مع GitHub.

## ما لم ينفذ والقيود

لا تطبيقات أو خادم جديد أو migrations أو قاعدة إنتاج أو إعداد خدمة خارجية. لا typecheck/build لمرجع Expo، ولا تشغيل أجهزة أو Push/OTA، ولا اختبارات تزامن PostgreSQL متعدد الاتصالات أو API/RBAC. اختيار إصدارات التطبيقات يبقى للتهيئة في 01 بعد مراجعة توافقها وقت التنفيذ.

لا يلزم طلب أسرار إضافية في هذه المرحلة. الحسابات وبيانات الإطلاق مؤجلة وفق قائمة REVIEW_00.md؛ لا خدمات تعمل إنتاجيًا مفترضة. لم يشتر مورد أو ينشر تطبيق.

## ما يحتاج قرار المالك

السجل الكامل D01–D21 في REVIEW_00.md. الأولوية: الفرع وأسعار الفروع، نموذج الحبة والكرتون، حساب الطريق والتقريب، مدة الحجز ومدة مراجعة الإيصال عند انتهائه، الإلغاء والحالة السادسة، والتحويلات والعمولة. يلزم أيضًا اعتماد سياسة الخصومات والصيانة، ثم بيانات الإطلاق والاحتفاظ والنسخ والخدمات في مواعيدها.

التصحيح الفني المقترح موثق بخيارات، وليس طلب موافقة على كل تفصيل برمجي روتيني. لا تعارض يمنع إنجاز المراجعة نفسها. اعتماد المالك مطلوب للقواعد التجارية قبل البناء عليها، كما يطلب نطاق المرحلة 00.
