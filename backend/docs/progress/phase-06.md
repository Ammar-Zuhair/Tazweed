# المرحلة06 — الكتالوج والخصائص والمخزون والملفات

نُفذت06 فقط بعد قراءة `remember.md` وتقرير05 وخطة06 ومراجعها: قرارات المالك والمتطلبات والقرارات وسجل المشكلات وMASTER_PROMPT، وDATABASE وBUSINESS_RULES وARCHITECTURE وSECURITY_OPERATIONS وAPI ووثيقتَي الشاشات. لم يذكر تقرير05 عائقًا يمنع تنفيذ06؛ غياب OTP وR2 عُزل صراحة وفق طلب المالك، ولم يُختبر المزودان الحقيقيان.

## النتيجة وحدود الحقيقة

أصبح PostgreSQL مصدر المحافظات والفروع والأقسام والخصائص والقيم والمنتجات ووحدات البيع وأسعارها ومخزون الفروع وحركاته ونقله. العميل والإدارة يستعملان API حقيقيًا دون الرجوع إلى fixtures عند الفشل. قاعدة المراجعة لا تحتوي حسابات أو منتجات مصطنعة؛ بيانات الأدلة أُدخلت في قواعد اختبار معزولة ثم حُذفت تلك القواعد.

الخدمات المؤجلة تظهر غير متاحة: لا إرسال طلب أو تسعير مسار أو حجز جديد أو اعتماد تحويل أو تسليم أو نقد أو عمولة محلية. كمية العميل قائمة اختيار فقط، وليست طلبًا أو تأكيد سعر/مخزون. الموصل شاشة انتظار لخدمته، دون مهام وأرصدة محلية معتمدة؛ لم تبدأ09. مصادر وتصاميم المعاينات السابقة محفوظة كمرجع تاريخي خارج المسارات النشطة. روابط الإدارة القديمة تفتح محرر الكتالوج الحالي؛ لا تعني ربط شاشات الطلبات أو المالية أو الموظفين القديمة بعد. الفيديو والخطوط والدوائر المضيئة الأصلية وExpo Go57 محفوظة، دون ادعاء فحص هاتف.

## الإعدادات والأسرار

سُجلت الأسماء الناقصة في **`backend/.env`**، مع حفظ القيم الموجودة، وصلاحية600 وgitignore. لا قيم سرية في التقرير أو Git. الإعدادات المطلوبة الآن:

- OTP: `OTP_PROVIDER` و`OTP_PROVIDER_URL` و`OTP_PROVIDER_TOKEN`.
- R2: `R2_ACCOUNT_ID` و`R2_ACCESS_KEY_ID` و`R2_SECRET_ACCESS_KEY` و`R2_PUBLIC_BUCKET` و`R2_PRIVATE_BUCKET` و`R2_PUBLIC_BASE_URL`.

يلزم وعاء عام للصور المعالجة، وآخر خاص للإيصالات وstaging، ونطاق عام وCORS محدد. بوابةOTP عقد HTTPS عام؛ قد يحتاج مزود بعينه محولًا لعقده. تفاصيل القيم المطلوبة والإعدادات المؤجلة في [ENVIRONMENT](../ENVIRONMENT.md). مفاتيح DB وEd25519 وHMAC جاهزة محليًا في إعدادruntime المحدود؛ لا يلزم نقلها أو إعادة توليدها لتهيئة OTP/R2.

HTTP يقرأ `.env.runtime.local` أساسًا ثم القيم غير الفارغة من `.env` ثم بيئة العملية، ولا يحمل اتصال مالك migrations. لا مفاتيح خدمة في frontend؛ بيانات جلسة المستخدم في SecureStore للأصلية وفي الذاكرة للويب. تدوير refresh متسلسل، وفقد إقراره ينهي الجلسة بدل إعادة استعمال التوكن القديم. تُعاد تهيئة شاشة الإدارة عند تغير الحساب حتى لا تنتقل بيانات جلسة سابقة إلى أخرى.

## الفحوص والأدلة

نجح **58 اختبارًا للخادم و73 اختبارًا لحراس SQL على PostgreSQL الفعلي**، مع **اختبارين إضافيين لمهلة العميل والإدارة بمكتبة الإلغاء الفعلية في React Native**؛ المجموع133 دون فشل. نجحت **19 حالة واجهة**: رحلة بيانات وصورة واحدة، و18معاينة للتطبيقات الثلاثة بالثيمين عند360/390/1024؛23لقطة و3QR. نجحت الأنواع والتصدير للويب وHermesAndroid/iOS، ومطابقةOpenAPI وفحص عدم تسرب مفاتيح الخادم إلى مصادر التطبيقات وحزمها، وmanifest والحزم6 وWebSocket3 والـAPI عبر الأنفاق.

توافق الشبكة الأصلي: React Native0.86 يستعمل abort-controller دون AbortSignal.timeout. استُبدلت المهلة بمتحكم إلغاء ومؤقت يشمل جسم الرد، مع تنظيفه فيfinally ورسالة آمنة عند انتهاء المهلة. الاختبار يستخدم المكتبة نفسها وHTTP فعليًا، ولا يُنسب إلى جهاز أصلي.

[ملخص الفحص القابل للقراءة الآلية](phase-06-checks.json)، [نتائج القبول الآمنة](phase-06-evidence/acceptance.txt)، [فهرس الصور والجولات](phase-06-evidence/README.md)، [فحص الأنفاق ووقت الفحص](phase-06-tunnels.json).

اختبارات API تعمل بحساب SQL محدود في قواعد PostgreSQL16 فعلية مؤقتة، وتجهيز fixtures بواسطةowner داخلها فقط. شملت 2×12+3=27، منع السالب وما دون المحجوز، منافسة على آخر مخزون، إعادة الحركة والنقل دون تكرار، وجوب الفرعين، فلاتر الزيوت دون المقاس، مؤشرات الفرع والأسعار والتعطيل والتصفح، الحجز المحمي وانتهاءtimed، وثبات التحويل المستخدم. الصور تفحص بايتات فعلية وإزالةEXIF ومصغرات وملكية وفشلMIME/size/expiry وتنظيفstaging دون حذف verified. حراسSQL المرجعية فحص مستقل، لا خدمة أعمال07/08.

رحلة المتصفح تستعمل واجهات Expo المصدرة وAPI وقاعدة PostgreSQL معزولة؛ اعتراض الطلبات يوجهها إلى الخادم الحقيقي المعزول، ولا يحقن حقائق UI. التقاطOTP ووسيط ملفاتR2 داخلprocess الاختبار فقط؛ لا طلبات إلى مزود حقيقي أو دخول تجريبي في خادم المراجعة. الفحص الأصلي على هاتف Expo Go، وSecureStore ورفع منتقي الصور على الهاتف، باقيان ولا تعوضهما حزمHermes أو فحص الويب.

مفتاح إعادة محاولة حركة المخزون يبقى في النموذج المفتوح؛ لا طابور دون اتصال دائم في06. إذا أُغلق النموذج بعد فقد الإقرار، يُراجع دفتر الخادم قبل إدخال حركة جديدة.

الجولات الأولى الموقوفة أو الفاشلة غير معتمدة؛ سجلP06-03..06 يوضح أسبابها وإعادة الفحص. npm audit: العميل20 والإدارة19، منها5عالية لكل منهما؛ نفس النتائج فيlock baseline قبل06 دون تنبيه مضاف. لم يُغيّر SDK أو يُستخدمforce لإخفائها. هذا ليس إصدار متجر أو اعتمادًا إنتاجيًا.
