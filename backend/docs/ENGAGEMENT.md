# الإشعارات والتشغيل — تنفيذ10

الخادم وPostgreSQL مصدر الحقيقة. وجود رسالة في المركز، أو نجاح ticket/receipt، لا يثبت ظهور إشعار على جهاز. لم تُختبر خدمات حقيقية أو يُنشر OTA في10؛ الجولة الأصلية مؤجلة حتى إضافة المفاتيح وطلب المالك. [OpenAPI10](openapi.phase10.json) مولّد من عقود المعالجة الفعلية.

## الأحداث والبث

عامل كل5ثوانٍ يقرأ outbox بعد commit. إنشاء رسالة المركز ومحاولات نقلها وتقدم cursor وحالة الحدث معاملة واحدة. قيدا UNIQUE(user,app,event_key) وUNIQUE(notification,token) يمنعان تكرار المركز وسجل محاولة الجهاز. تشمل الأحداث: الطلب الجديد، والعرض وقبول العميل أو رفضه، ورفع الإيصال وتصحيحه وتأخر مراجعته، والتأكيد والإلغاء والطريق والتسليم والإسناد، والبلاغ والشكوى وردها. الإعلان الترويجي يتم عبر بث صريح؛ لا يولد كل تعديل كتالوج إعلانًا.

المحتوى التشغيلي عام، دون عنوان أو هاتف أو مبلغ أو صورة إيصال. بيانات Push تحمل معرف الإشعار والتطبيق والمستلم فقط؛ يجلب التطبيق التفاصيل من API. تُفحص الملكية وصلاحية الموظف وفرعه والإسناد الحالي في قراءة المركز وقبل النقل. لا يفتح الموصل مهمة أُلغي إسنادها، حتى إن كان قد استلم رابطها.

البث يحتاج `notifications.broadcast` عامًا قبل idempotency replay وداخل المعاملة. تحفظ مسودة ثابتة ثم تُجدول بتوقيتUTC، أو تُلغى قبل بدء الإسقاط فقط. لا يدعي الإلغاء سحب رسائل خرجت. الجمهور all/customers/couriers، مع فرع اختياري: عملاء لهم طلب في فرع الكتالوج أو التنفيذ المحدد، وموصلوه وموظفوه المخولون. ليس كل سكان المحافظة أو زوار الكتالوج.

القوائم cursor≤100، ودفعة المستلمين200 مع استئناف UUID. يُحسم الجمهور الحي في كل دفعة، وليس snapshot ثابتًا لجميع المستخدمين. سحب صلاحية الكاتب يوقف الدفعات التالية بـfailed/AUTHOR_REVOKED. حالة sent للحملة تعني اكتمال إنشاء الرسائل فقط؛ قد يبقى Push غير مهيأ أو يفشل. البيئة محفوظة في الحملة، ولا يستهلك العامل حملات أو محاولات بيئة أخرى. لكل من staging وproduction قاعدة وأسرار مستقلة؛ لا يشغلان outbox مشتركًا.

## الرموز والنقل

POST `/devices/push-tokens` يقبل ExpoPushToken، لا رمز FCM/APNs الخام. نوع التطبيق من الجلسة الموثقة، والبيئة من الخادم، وprojectId يطابق الإعداد الصريح. يحفظ الرمز جلسة مالكه وplatform وتفضيل الصوت وgeneration، ولا يظهر في DTO أو logs. لا يستطيع حساب آخر أخذ رمز مرتبط بجلسة نشطة. logout يبطل رموز جلسته ذريًا؛ وإبطال الجلسة أو تعطيل الحساب/الموصل يمنع النقل بالفحص الحي. DELETE يعطل رموز الجلسة الحالية، ويستعمل أيضًا عند رفض الإذن.

إعادة التفعيل المطابقة لا تسقط المحاولات المعلقة. تغيير الصوت لا يبدل generation؛ تغيير المالك أو الجلسة أو إبطال الرمز يبدلها. يتصل المحول بمساري Expo HTTPS الثابتين فقط، مع Bearer وenhanced push security ومهلة تشمل جسم الرد ومنع redirects. مطالبات العمل تستخدم SKIP LOCKED وlease90ثانية، وتسجيل النتيجة مشروط بنفس lease. الإرسال حتى5محاولات مع backoff، ومراجعة receipt كل15دقيقة حتى96مرة.

قبول التذكرة يسجل sent. نجاح receipt يسجل delivered بمعنى **التسليم لخدمة FCM/APNs فقط**. DeviceNotRegistered يبطل generation المطابقة دون المساس بنسخة أحدث. الأخطاء الدائمة لا تعاد بلا حد، ولا تحفظ رسالة المزود الخام.

Push يعمل بأسلوب at-least-once: فقد إقرار Expo بعد قبوله قد يؤدي إلى تكرار التنبيه عند المحاولة؛ لا ضمان exactly-once عبر الشبكة ونظام الهاتف. المركز ثابت مرة واحدة، والتطبيق يمنع تكرار الفتح والتنبيه المعروف خلال الجلسة. لا يمكن سحب رسالة غادرت إلى المزود قبل revocation، ولا يعرف الخادم بخروج دون شبكة حتى يصل طلب الإبطال. foreground يتحقق من app/user وتصريح API ضمن مهلة قصيرة؛ فتح إشعار حساب سابق لا يكشف طلبه. فشل Push لا يفشل الطلب أو العملية المالية.

الصوت default من النظام، بقناتَيAndroid ثابتتين `tazweed-alerts-v1` و`tazweed-silent-v1` وتفضيل محفوظ لكل حساب. لا تشغيل صوت خلفي عبر expo-audio أو طلب ميكروفون. قد يمنع إذن النظام أو الكتم أو إعداد القناة الصوت. foreground له handler؛ background/closed يعتمدان FCM/APNs والنظام، وforce-stop غير مضمون. Go/web لا يسجلان رمزًا مزيفًا، ويظل المركز متاحًا.

## الصيانة والإصدارات

PUT `/admin/customer-maintenance` يحتاج maintenance.write عامًا وexpectedVersion. ترفض catalog/preview/submit بـ503MAINTENANCE وRetry-After60، دون إعادة تلقائية للكتابة. يأخذ submit قفل FOR SHARE لسطر الصيانة داخل معاملته؛ التبديل ينتظر العمليات التي بدأت قبله، ولا يبدأ طلب جديد بعد حاجز الصيانة. الطلبات الجارية وتفاعلاتها والهوية والمركز والملفات والدعم والخصوصية والحذف خارج الحجب، وكذلك الإدارة والموصل. خدمات الدعم والحذف الكاملة في11؛ الصيانة لا تضيف حاجزًا عليها ولا تدعي إنجازها.

GET `/public/config?app&platform&build` يرفض environment من العميل؛ البيئة من APP_ENV. build رقم أصلي، وbuild0 للويب/Go لا يفرض بوابة متجر تخص binary أخرى. minimum إجباري، وlatest اختياري قابل للتأجيل. تعديل الإصدار يحتاج releases.write عامًا وexpectedVersion، مع app/platform ورابط HTTPS لمتجر المنصة وbinaryConfirmed=true كإقرار الموظف بتوفر النسخة. ليس ذلك فحص متجر شبكيًا؛ يجب التحقق من الحزمة والرابط الفعليين قبل رفع minimum. بوابة الإصدار واجهة تشغيل وليست تصريح هوية أو بديلًا عن توافق API.

يستخدم app.config بيانات بناء عامة فقط وقنوات مستقلة وruntimeVersion fingerprint. يفحص OTA وينزله مرة بعد root، دون reload أو تكراره عند كل foreground؛ الفشل يبقي النسخة الجارية. تتحقق Expo من توافق runtime في check/fetch. تغيير native يحتاج binary جديدة، ولا يوجد هنا أمر ينشر OTA أو يتجاوز التوافق.
