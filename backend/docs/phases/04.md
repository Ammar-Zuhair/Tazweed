## المطلوب في هذه المرحلة فقط
نفذ courier-app/docs/SCREENS.md بمهام متعددة وملاحة ومبالغ يومية وبلاغات. أكمل مراجعة الاتساق عبر التطبيقات واكتب UI_REVIEW.md. لا تبدأ منطق backend قبل تسليم هذه المراجعة.

## مخرجات القبول
لا زر رفض، لا فيديو موصل، لا تتبع خلفي، تحديد الفرق بين pending network والنجاح. كل شاشات التطبيقات الثلاثة قابلة للمراجعة.

## عند الانتهاء
حدّث remember.md واكتب backend/docs/progress/phase-04.md بالملفات والفحوص والنتائج والنواقص. توقف بعد هذه المرحلة؛ لا تبدأ المرحلة التالية حتى تُطلب في رسالة منفصلة. اتخاذ قرارات التنفيذ الروتينية داخل هذه المرحلة مأذون.

## ما يراجعه المالك بعد التسليم
راجع المهام المتعددة والعنوان والملاحة وبدء التوصيل والتسليم والمستحقات والبلاغات. راجع UI_REVIEW.md للتطبيقات الثلاثة، ثم اطلب إصلاح الواجهات واعتمدها قبل المرحلة05.

أرفق دليلًا مناسبًا: معاينات وتشغيل للشاشات، ونتائج أوامر واختبارات للمنطق. لا تكفي عبارة «تم» أو فهرس ملفات كدليل إنجاز.
