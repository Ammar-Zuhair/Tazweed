# التوصيل والتحصيل والعمولة والجودة —09

العقد التنفيذي الحالي [OpenAPI09](openapi.phase09.json). المبالغ ريالات صحيحة في JSON كنصوص؛ `expectedVersion` عدد صحيح، و`Idempotency-Key` ثابت لكل محاولة منطقية. كل أمر يتحقق من التفويض الحي قبل replay وداخل معاملته. لا يرسل التطبيق نجاحًا قبل إقرار الخادم؛ النتيجة المجهولة تعاد بالمفتاح والمحتوى المحفوظين للحساب نفسه.

## الإسناد والمهمة

- الموظف يحتاج `orders.assign` على الفرع الحالي والتاريخي. يسند الطلب المؤكد كله لموصل نشط، ذي فرع مسموح ونسبة صريحة، ويمكن إسناد عدة طلبات للموصل. إعادة الإسناد قبل بدء الطريق فقط؛ تحفظ assignments السابقة. نسبة NULL ليست صفرًا، أما صفر صريح فمسموح.
- يحفظ الإسناد `commission_bps` ورسوم التوصيل قبل الخصم وخصمه والعمولة: `round(delivery_yer * commission_bps / 10000)`؛ النصف للأعلى. مثال500−100،20%→عمولة100 وتوصيل العميل400. تغيير نسبة الموصل لاحقًا لا يعيد حساب الإسناد.
- `confirmed → on_the_way → delivered`. قفل الطلب وقفل الموصل وسجل الأحداث والتدقيق وoutbox في معاملة واحدة. التسليم يسجل earning موجبًا مرة واحدة، ولا يكتب صفًا ذا مبلغ صفر ولا أي تحصيل تلقائي.
- الموصل يرى مهامه الحالية في فروعه فقط: بيانات الاتصال والعنوان الضرورية والبنود وحالة الدفع ومبالغ التحصيل وsnapshot عمولته. لا إيصالات التحويل أو إثباتات الموظفين أو أرشيف بلاغات العميل. بعد إعادة الإسناد يُمنع الموصل السابق من التفاصيل والعمليات. فتح اتصال/WhatsApp/خرائط خارجي فعل صريح؛ لا تتبع موقع خلفي.
- حسابات الموصلين ينشئها موظف عام مخول بـ`couriers.manage`، ثم يضبط الاسم والنشاط والفروع والنسبة. الإدخال في الواجهة بالنسبة المئوية، وسجل إعداداته يعرض النسبة والنشاط وعدد الفروع ووقتUTC منaudit immutable؛ لا يعرض معرّفات فروع تاريخية غير لازمة. لا يمكن تعطيل/إزالة فرع ذي مهمة جارية. الدخول الفعلي يحتاج OTP من المزود لاحقًا، لا رمزًا ثابتًا في الواجهة.

## النقد الفعلي والاستثناءات

- التحصيل أمر مستقل بمبلغ موجب ومرجع ووقت وقوع غير مستقبلي. لا ينشأ من قبول النقد أو تأكيد الطلب أو تسليمه. التحويل لا يقبل تحصيلًا نقديًا. يوجد أصل تحصيل واحد للطلب؛ تصحيحه للإدارة بـ`cash.adjust` كقيد تعويضي مسبب ذي مرجع وإثبات خاص، دون تعديل الأصل أو جعله سالب الصافي.
- الفرق عن المستحق يحتاج استثناء صريحًا: `cash_uncollected` أو`cash_shortfall` أو`overpayment`، مع السبب والمبلغ والفرع. التسليم يحتاج معرّف استثناء يطابق الفرق الحالي. يبقى التحصيل الفعلي كما سجل؛ لا تتحول التسوية الخارجية إلى مال بيد الموصل.
- إغلاق استثناء COD يحتاج صافي فجوة صفر بعد استلام خارجي/رد/شطب موثق. الشطب قرار محاسبي لا زيادة في التحصيل. تُحفظ حركة السبب والمرجع والإثبات والمسؤول ووقت الوقوع. قواعد التحويل اليدوي08 تبقى مستقلة.
- الرصيد النقدي للموصل = مجموع التحصيل والتصحيحات + credits العكس − التوريدات. العمولة دفتر آخر تمامًا. لا طرح عمولة من مال المتجر ولا محفظة/رد آلي. قد يظهر رصيد سالب بعد تصحيح موثق لمبلغ سبق توريده؛ لا نعيد كتابة توريده، وتستكمل الإدارة المصالحة بقيود لاحقة موثقة.

## الصرف والتوريد والعكس

- الإدارة تختار earning IDs أو collection IDs أو reversal credit IDs صراحة، ومجموعها يجب أن يطابق المبلغ الموجب المرسل. الصف المختار بكامله يخصص مرة واحدة. التصحيحات السالبة تُجمع مع مصادر موجبة في تخصيص إجماليه موجب.
- قفل واحد لكل موصل ينسق التحصيل والتسليم والتصحيح والصرف والتوريد والعكس. التخصيصات الفريدة وحراس SQL تمنع دفع بند/credit مرتين، حتى مع مفتاحين متزامنين. لا `UPDATE/DELETE` للدفاتر في runtime، ولا توسيع لصلاحياتها لأجل أقفال الصفوف.
- العكس كامل مرة واحدة للأصل وبصلاحية منفصلة، مع سبب ومرجع وإثبات `financial_proof` خاص متحقق مملوك للموظف. يحفظ الأصل وتخصيصاته، وينشئ credit بالقيمة نفسها يمكن إعادة صرفه/توريده مرة واحدة؛ لا يعيد استحقاق عمولة التسليم. لا عكس جزئي أو مقاصة تلقائية.
- قراءة الدفتر وإجراءاته تتطلب نطاق جميع فروع الموصل الحالية والتاريخية. حذف فرع من ملفه لا يكشف مالًا تاريخيًا لموظف محدود. اختيار الموصل المالي مستقل عن صلاحية إدارة حسابه. قراءة متسقة `REPEATABLE READ READ ONLY`، والدفتر يعرض البنود والتخصيصات والعكس. التجميع الحالي كامل تاريخ الموصل؛ التصفية والتقارير والتصدير الأوسع في مراحلها اللاحقة.

## الجودة والخصوصية

- العميل صاحب طلب delivered يقيّم1–5 مرة واحدة، ويمكنه رفع شكوى بنص وصورة خاصة اختيارية. مراجعة الموظف بـ`complaints.manage` تحفظ الرد والحالة والإصدار والتدقيق دون تغيير نص العميل. يظهر الرد لصاحب الطلب.
- الموصل الحالي أو موظف مخول يبلغ `customer_flag` أو`delivery_problem` بنص وصورة خاصة اختيارية. يُربط العميل من الطلب في الخادم. تنبيه البلاغ السابق يظهر للإدارة في طلب العميل اللاحق قبل إصدار العرض/التأكيد، دون حظر تلقائي. خارج نطاق الفرع التاريخي يظهر تنبيه وجود فقط دون نص أو مرفق.
- طلب رابط الصورة الخاصة يراجع الملكية/الدور/الفرع عند كل طلب توقيع؛ الرابط مؤقت، ولا يعني سحب الصلاحية إبطال رابط سبق توقيعه قبل انقضاء مدته. المرفق المرفوع لا يبرر كشف ملف مرتبط بعد زوال الصلاحية. ردود الشكاوى ومراجعات البلاغات ذات version لمنع الكتابة المتزامنة الصامتة.
- إشعار المهمة الجديدة حاليًا علامة وقائمة وتحديث من الخادم، وoutbox ضمن المعاملة. إرسال Push وصندوق الإشعارات في10، ولم ينفذا ضمن09. تواريخ الواجهة و«اليوم» موسومة UTC؛ قرار Asia/Aden ما زال غير محسوم.

## المسارات والشاشات

| الوظيفة | العقد |
|---|---|
| الإسناد | `POST /admin/orders/{id}/assign` و`GET .../courier-options` |
| المهمة | `GET /courier/orders`،`GET /courier/orders/{id}`،`POST .../start` و`.../deliver` |
| النقد | `POST .../cash-collections` و`.../cash-exceptions`،`POST /admin/cash-collections/{id}/adjustments` |
| حساب الموصل | `GET/POST /admin/couriers`،`POST /admin/couriers/{id}/configure` و`GET .../configuration-history`؛ ضبط النسبة والفروع معًا ببديل موثق لمساراتPATCH التصورية |
| الدفاتر | `GET /courier/earnings` و`/courier/cash-balance`؛ للإدارة `/admin/couriers/{id}/earnings` و`.../cash-balance`، وتشمل مصادر الدفتر والصرف/التوريد وتخصيصاته |
| اختيار مالي | `GET /admin/couriers/ledger-options?kind=cash|commission` |
| التخصيص والعكس | `POST /admin/settlements` و`/admin/cash-remittances`،`POST .../{id}/reversals` |
| الجودة | `POST /orders/{id}/review` و`.../complaints`؛`POST /courier/orders/{id}/customer-flags` و`/admin/customer-flags`؛ قوائم `/admin/{complaints,customer-flags,reviews}` ومراجعة أوليين بـ`POST .../{id}/review` |

القوائم تستخدم cursor UUID وlimit1–100(default30). لا قائمة مالية عامة تكشف فروعًا أخرى؛ سجلات الصرف والتوريد ضمن دفتر الموصل المفوض نفسه. واجهة الموصل `/` و`/task` و`/earnings` و`/cash` و`/report` و`/pending` و`/account`، والإدارة `/orders` و`/couriers` و`/finance` و`/quality`، والعميل `/order` و`/review` و`/complaint`.

لا مفاتيح خدمات جديدة لهذه المرحلة. R2 السابق للمرفقات وOTP السابق للدخول، ولا Push أو بوابة دفع أو Routing جديد. اختبارها الحقيقي والأجهزة الحقيقية بعد طلب المالك؛ أدلة09 تستخدم محولات معزولة وقاعدة اختبار مؤقتة، لا بيانات متجر مصطنعة في قاعدة المراجعة.
